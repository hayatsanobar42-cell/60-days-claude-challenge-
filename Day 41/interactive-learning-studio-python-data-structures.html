📦 Module 1 — Lists: The Foundation

Difficulty: Foundational

A list is Python's ordered, mutable collection — the workhorse data structure you'll reach for most often. Think of it as a row of numbered lockers: each locker holds one item, has a fixed position (index), and you're free to open any locker and swap its contents.

🔍 Anatomy of a List

fruits = ["apple", "banana", "cherry", "date"]
#            0         1         2        3   <- index
print(fruits[1])      # "banana"
print(fruits[-1])     # "date"  (negative index counts from the end)
print(fruits[1:3])    # ["banana", "cherry"]  (slicing)

🎭 Analogy

A list is like a numbered coat check at a theater: every coat (item) hangs on a labeled hook (index) in a specific order, and you can add, remove, or swap coats anytime — the row simply renumbers itself.

🛠️ Core Operations

Adding

fruits.append("fig")     # add to end
fruits.insert(1, "kiwi")  # add at index 1

Removing

fruits.remove("banana")  # by value
fruits.pop()              # remove & return last
del fruits[0]             # by index

Modifying

fruits[0] = "apricot"     # lists are mutable!

Iterating

for i, f in enumerate(fruits):
    print(i, f)

✨ List Comprehensions

A compact, Pythonic way to build lists from existing iterables:

squares = [n**2 for n in range(10) if n % 2 == 0]
# [0, 4, 16, 36, 64]

⚖️ Comparison: Lists vs. Arrays (other languages)

Python List
Dynamic size, mixed types allowed, built-in methods, slightly more memory overhead.
Fixed Array (C/Java)
Fixed size, single type, faster raw access, manual resizing required.

⚠️ Common Misconceptions

"Copying a list with b = a makes a new list."
False! This creates a second name pointing to the same list object. Mutating b mutates a too. Use b = a.copy() or b = a[:] for a real copy.
"Slicing always returns the original list."
False — slicing (a[1:3]) always returns a new list, unlike a plain assignment.

✅ Key Takeaways

  • Lists are ordered and mutable — index access is O(1), but insertion/search at arbitrary positions is O(n).
  • Use .copy() or slicing to avoid accidental aliasing.
  • List comprehensions are the idiomatic way to transform/filter data.

🔗 Module 2 — Tuples & Immutability

Difficulty: Foundational → Intermediate

A tuple looks like a list but is immutable — once created, its contents can't change. Tuples represent fixed collections of data, like coordinates or database records.

🔍 Anatomy of a Tuple

point = (3, 4)
person = ("Alice", 30, "Engineer")
single = (5,)   # trailing comma required for one-element tuples!

🎭 Analogy

A tuple is like a sealed birth certificate: the facts (name, date, place) are fixed the moment it's issued. You can read it, copy it, reference it — but you can never edit the original document.

🛠️ Core Operations

Unpacking

x, y = point
name, age, role = person

Immutability in action

point[0] = 10
# TypeError: 'tuple' object does
# not support item assignment

⚖️ Comparison: Tuple vs. List

Tuple
Immutable, hashable (usable as dict keys/set members), slightly faster, signals "fixed data."
List
Mutable, unhashable, more flexible for data that grows/shrinks.

⚠️ Common Misconceptions

"Tuples are just slower lists." Not quite — tuples are actually slightly faster to create and iterate, and their immutability lets Python optimize memory. They're also the only one of the two that can be a dictionary key.
"(5) is a tuple." False! (5) is just the integer 5 in parentheses. You need the comma: (5,).

💻 Interactive Exercise: Fix the Bug

🧩 Practical Exercise: Tuple Unpacking

Given record = ("Nina", "Kanpur", 27), write the unpacking line to assign name, city, age.

✅ Key Takeaways

  • Tuples are ordered but immutable — perfect for fixed records and dict keys.
  • Single-element tuples require a trailing comma.
  • Unpacking works for both tuples and lists.

🗂️ Module 3 — Dictionaries: Key-Value Power

Difficulty: Intermediate

A dict stores data as key-value pairs, giving near-instant lookups by key rather than position. It's the structure behind JSON, configuration files, and countless real-world data models.

🔍 Anatomy of a Dictionary

student = {
    "name": "Ravi",
    "age": 21,
    "courses": ["Math", "CS"]
}
print(student["name"])       # "Ravi"
print(student.get("gpa", "N/A"))  # safe lookup with default

🎭 Analogy

A dictionary is like a real dictionary book — you don't scan every page to find "cat"; you jump straight to the word (key) to read its definition (value). That's why key lookups are near O(1) instead of O(n).

🛠️ Core Operations

Adding / Updating

student["gpa"] = 8.7
student.update({"age": 22})

Removing

del student["age"]
gpa = student.pop("gpa")

Iterating

for key, value in student.items():
    print(key, "->", value)

Dict Comprehension

squares = {n: n**2 for n in range(5)}
# {0:0, 1:1, 2:4, 3:9, 4:16}

⚖️ Comparison: Dict vs. List for Lookup

List search
x in my_list checks every element → O(n).
Dict search
x in my_dict uses hashing → average O(1), dramatically faster for large data.

⚠️ Common Misconceptions

"Dictionaries are unordered." True before Python 3.7 — but since 3.7, dicts preserve insertion order as a language guarantee.
"Any type can be a dict key." False — keys must be hashable (immutable), so lists and dicts can't be keys, but tuples and strings can.

💻 Interactive Exercise: Safe Lookup

Given scores = {"amit": 90, "sara": 85}, write code to look up "zoya" and print "N/A" if she's missing, without raising a KeyError.

✅ Key Takeaways

  • Dicts map unique, hashable keys to values with fast average O(1) lookup.
  • Since Python 3.7, insertion order is preserved.
  • Use .get() for safe lookups that avoid KeyError.

🎯 Module 4 — Sets & Choosing the Right Structure

Difficulty: Advanced / Mastery

A set is an unordered collection of unique elements, optimized for membership testing and mathematical set operations like union and intersection.

🔍 Anatomy of a Set

tags = {"python", "code", "python", "tutorial"}
print(tags)   # {'python', 'code', 'tutorial'} -- duplicates gone!
tags.add("beginner")
print("code" in tags)   # True, O(1) average lookup

🎭 Analogy

A set is like a guest list at a party door: the bouncer only cares whether your name is on the list or not — no duplicates, no order, just fast yes/no checks.

🛠️ Set Operations (Math meets Code)

Union a | b
All elements from both sets.
Intersection a & b
Elements in both sets.
Difference a - b
In a, not in b.
python_devs = {"Amit", "Sara", "Ravi"}
js_devs = {"Sara", "Zoya", "Ken"}
print(python_devs | js_devs)   # union: all devs
print(python_devs & js_devs)   # intersection: {'Sara'}
print(python_devs - js_devs)   # difference: {'Amit', 'Ravi'}

⚖️ Master Comparison: Choosing the Right Structure

StructureOrdered?Mutable?Duplicates?Best For
ListYesYesYesOrdered, changeable sequences
TupleYesNoYesFixed records, dict keys
DictYes (3.7+)YesKeys: NoFast key→value lookup
SetNoYesNoUniqueness & fast membership

⚠️ Common Misconceptions

"Sets keep insertion order like dicts." False — sets are unordered; never rely on their iteration order.
"You can put a list inside a set." False — set elements must be hashable, so lists (mutable) are rejected; use tuples instead.

💻 Interactive Exercise: Remove Duplicates

Given nums = [1, 2, 2, 3, 3, 3], write the shortest expression to get the unique values.

✅ Key Takeaways

  • Sets guarantee uniqueness and offer O(1) average membership tests.
  • Use union/intersection/difference for set algebra instead of manual loops.
  • Choosing a structure = balancing order, mutability, uniqueness, and lookup speed.

🏆 Final Practical Challenge

You're building a small student-records system. Given raw data, combine everything you've learned:

Task: Write a dict comprehension that maps each student name (key) to their set of unique course tags (value), from this list of tuples:

records = [
    ("Amit", "Math"), ("Amit", "CS"),
    ("Sara", "CS"), ("Sara", "CS"), ("Sara", "Art")
]
# Goal: {"Amit": {"Math","CS"}, "Sara": {"CS","Art"}}
Sample solution: 
from collections import defaultdict
result = defaultdict(set)
for name, course in records:
    result[name].add(course)
result = dict(result)
